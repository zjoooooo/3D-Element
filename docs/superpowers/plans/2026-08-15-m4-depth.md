- [ ] **Step 3: 实现**

TideSchedule：构造器的洗牌循环抽成方法并导出常量：

```js
/** 相生 across the cycle: FEEDS[i] is the element i generates. */
export const FEEDS = [2, 3, 1, 4, 0];

  reshuffle(rng) {
    for (let i = this.order.length - 1; i > 0; i--) {
      const j = (rng() * (i + 1)) | 0;
      const swap = this.order[i];
      this.order[i] = this.order[j];
      this.order[j] = swap;
    }
  }
```

（构造器改调 `this.reshuffle(rng)`。）RunManager.start() 首行区加 `this.s.tides.reshuffle(this.s.rng);`（App 里"重开同潮序"的注释同步删改）。RunHud 删 `showVerdict`（M3 勘误标记的死代码；grep 确认无调用者后删）。

/* ---- marks, reactions, debuff channels ---- */
{

  const i = enemies.spawnAt(0, 0, 0, 0, 0, 0); // metal enemy, plenty irrelevant
  enemies.hp[i] = 1000;

  let reacted = null;
  enemies.onReaction = (markWux, wux, x, z, amount) => (reacted = [markWux, wux, amount]);
  const hpBefore = enemies.hp[i];
  enemies.damage({ x: 0, z: 0 }, 1, 10, 3);
  assert.deepEqual(reacted?.slice(0, 2), [1, 3], 'marks: 木→火 detonates 助燃');
  const expected = 10 + 10 * settings.marks.reactionMult; // hit + detonation
  assert.ok(Math.abs(hpBefore - enemies.hp[i] - expected) < 1e-6, 'marks: detonation adds ×1.5');
  assert.equal(enemies.mark[i], 255, 'marks: detonation consumes the mark');

  // Debuffs: a metal hit on wood applies vuln, and vuln amplifies the next hit.
  enemies.clear();
  const w = enemies.spawnAt(0, 0, 0, 1);
  enemies.hp[w] = 1000;
  enemies.damage({ x: 0, z: 0 }, 1, 10, 0); // 金克木 → vuln 15%

  );

  // 熄灭: a water hit on fire weakens its bite.
  enemies.clear();

/**
 * 相生轮转 (spec §4.8): casting along the generating cycle within the window
 * halves the second cast's cooldown. Pure so the check script can pin it.

export function sequenceRefund(prevWux, prevAt, wux, now) {
  if (prevWux < 0 || wux < 0) return false;

**计划文本缺陷**（落笔时发现，均已按裁定修正）：
- T4（D-M4-2）：计划给的燃烧断言求和在 fade 阶段夹具下无法满足（该夹具只引爆一次，+55 的量对不上）——实现者的"按引爆次数过滤"判为正确，评审手工复算通过。

**裁定**：
- D-M4-1（引爆命中的 matchup）：引爆是否保留克制倍率——保留（"克制必生效"：引爆的相生加成是叠加在已结算伤害之上的额外 payoff，不是替代），计划原文给的锚 5 数值 25 是算术错误，正确值 27.5。
- exhaustion-test 语义（T8）：耗尽测试原断言的"空手"预期在 spec §4.7"融合无条件触发"下已经站不住——改判为稳定拿到那唯一一张金卡（8 个成熟有序对手工核对过）。
- aim 借用还原方式（T9）：捕获前值、用完直接 capture/restore 写回，不上 try/finally 或改造调用结构——评审确认与代码库既有风格一致，落 Minor 存档。

**保留语义**（非缺陷，记录设计意图/当前状态）：
- 融合可用对子中有两对（火→土、土→金，即任何一头挂土的）在土系技能落地（M6）前不可达——`eligibleFusions()` 本身没问题，只是 `wuxingOf` 里当前没有技能映射到土（wux 4）。同一原因下，土共鸣与周天也处于休眠：`_resonance[4]` 永远是 0。
- top3 的技能记账是"按 wuxing 找第一个配置的同系技能"近似（`wuxingRep`），不是精确的施法者追踪，与结算其余账本同一精神；土系目前无技能可记，`wuxingRep(4)` 返回 `undefined` 时记账被显式跳过，不是丢失或报错。
- 三条施放口——手动 `_cast`、echo（经 `_quickCast`）、挂机 `_quickCastToward`（含其融合分支）——写冷却后都会调用共享的 `_applySequence`，相生轮转对三者一视同仁；这是 T7 修复后的稳定状态，该方法自身注释已把"或链条静默失效"钉在这条不变量上。
